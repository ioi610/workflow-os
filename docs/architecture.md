# 技术与业务约定

## 当前产品范围

WorkFlow OS 用于安排工作流程，并保存每项工作的具体做法。首页把流程卡片与「工作清单」放在同一页，不显示全局侧栏、顶部栏、手机底栏或介绍横幅。流程图是一块不分格的画布，默认正方形，整张图可以缩放显示；工作方框和加号入口的初始宽、高各占画布的五分之一。显示缩放不改写工作方框的逻辑位置和大小。用户通过拖动和箭头安排先后顺序，点击工作名称阅读自己编写的做法。

流程列表的方框入口中央显示加号与「添加流程」，点击进入 `/workflows/new`，填写后仍需点击「添加流程」创建，不会在输入过程中自动创建。完整编辑器的两个标签为「安排工作」和「写具体做法」；从工作名称进入时只显示当前做法的阅读或编辑界面，不显示其他工作导航或全部做法；已有流程的编辑器和流程图均自动保存，不显示保存按钮。下方「工作清单」逐行展示工作名称、编号、所属流程、具体做法和操作，可以搜索或按流程筛选；每行的「在流程里查看」打开正确的工作方框。旧 `/manager` 地址仍重定向到 `/`。

界面统一使用「工作」「流程图」「工作清单」「具体做法」等直接的名称。内部 `MODULE`、`DETAIL`、`work_items`、SOP、路由和数据库字段保持原样；下文技术段的模块指界面的工作，模板指保存的流程。用户已有名称、正文、图片与数据不会因为界面改名而修改。今日任务、完成状态、关注提示、统计、计划、日期、地点、交接和管理台仍没有界面入口。

## 分层

前端 `src/features/sop` 承载整合首页、流程图、工作清单与编辑器；手册设置页面及其入口已移除，账户模式另提供登录功能。`src/components` 提供基础界面组件，`src/api.ts` 处理 Cookie / CSRF 请求；React Router 管理路由，TanStack Query 管理服务端状态。当前流程数据按组织查询，不以日期或地点作为使用前提。工作清单通过独立查询读取持久化工作记录，流程查询仅用于解析模板和详细做法链接，不再临时展开模块来充当记录，也不创建完成状态。

后端仍是单体应用：`auth` 负责账户与个人模式初始化，`Access` 统一会话、组织成员和租户资源校验，`WorkspaceController` 管理流程保存及现有配置接口，`MediaController` 管理受保护的图片。实体集中在 `Model`。

现有 `PlanningController`、`ruleengine`、模板、计划、任务执行、交接与相关实体继续保留以兼容已有数据和接口。当前前端不使用这些模块，当前简化无需删除历史数据。个人模式新增 V3 迁移，用于记录本机固定身份与默认手册。

应用没有使用 AI 服务、API Key 或用户脚本执行器。运行环境为 Java 21 / Spring Boot 3.5 与 Node.js 22.12+，本地与容器启动方式见 README。

## 视觉主题

`src/theme.css` 统一暖纸白、深森林绿及相关文字、边框和表面色，并统一卡片、加号、按钮、表单、流程图、工作清单、具体做法与弹窗样式。`main.tsx` 在基础样式后引入该主题，使组件共享视觉规则；主题调整不改变路由、业务操作、数据结构或保存方式。桌面与手机继续使用既有响应布局。

## 个人模式与账户模式

`application-local.yml` 开启 `workflow.personal-mode=true` 并将后端绑定到 `127.0.0.1:18080`；`start-local.sh` 默认使用此配置。未启用 `local` 的默认后端与 Compose 保留账户模式；默认开发后端为 8080，前端可用 `WORKFLOW_API_TARGET` 切换代理目标。

前端先读取 `GET /api/mode`，个人模式自动请求 `POST /api/personal/bootstrap`，使用 HttpOnly 会话访问原有业务接口。该写请求仍需要 CSRF。`personal_installation` 单行记录通过外键固定个人身份和默认手册，首次初始化用数据库锁串行处理，避免新浏览器会话反复创建身份。首次选择优先沿用当前已登录用户及其工作手册，其次沿用本机已选手册对应的所有者；已经固定后不会被后来的会话或手册提示替换。

个人模式界面隐藏登录、注册、邮箱、账户和退出入口。原手册设置地址 `/me` 重定向到 `/`；页面不再显示全局导航栏。已有多本手册时，仅在首页分类工具区显示紧凑的「切换工作内容」选择器，继续访问原数据；只有一本手册时不显示选择器，当前界面不再单独提供新建额外手册的表单。会话失效后自动恢复本机身份；清除浏览器存储不会删除数据库中的工作流程。此模式表示访问本机应用即可使用个人手册；它不作为公开、多用户服务的访问控制。账户模式继续使用原有注册、登录及角色检查，首次没有组织时仍有必要的初始化表单。当前没有收费、支付、授权码兑换或免密码认证实现。

## 组织隔离和角色

每次业务请求先读取会话 userId，再检查该用户是否为目标组织的 ACTIVE 成员。租户资源查询限制 organizationId，或校验实体所属组织；文件和版本查询执行相同的归属检查。

| 当前界面操作                                 | OWNER | MANAGER | EMPLOYEE |
| -------------------------------------------- | ----- | ------- | -------- |
| 查看和分类阅读流程                           | 是    | 是      | 是       |
| 添加、修改、删除流程和工作，移动与连接并保存 | 是    | 是      | 否       |
| 切换已有工作内容                             | 是    | 是      | 是       |

Spring Security 启用 CSRF，业务权限由后端 Access 检查。前端隐藏编辑按钮用于表达权限，不能替代服务端检查。旧管理接口继续沿用其原有角色限制，但当前界面不提供管理台入口。

## 流程内容与保存

SOP 是工作流程在现有存储层中的名称。`Sop` 保留标题、分类、修订号、可编辑的 `draft` 步骤 JSON 与原有版本引用，`SopVersion` 保留历史快照。前端按保存内容直接展示工作流程，不再要求用户先保存草稿、再单独发布。

`steps` 数组保存两种内容：

- `MODULE`：`id`、`title`，用于流程首页的模块链接框；可带 `detailWorkflowId` 和 `detailId`，固定已匹配的具体做法来源及文档编号；未创建流程的本地做法只存 `detailId`，含义为本地绑定。`position: {x, y}` 为左上角相对画布的坐标；可带 `size: {width, height}`，两个尺寸均为画布比例，缺失时各按 0.2 读取。位置范围由尺寸决定，满足 `0 ≤ x ≤ 1 - width`、`0 ≤ y ≤ 1 - height`；`nextModuleIds` 保存箭头终点标识，`connectionPorts[targetId] = {source, target?}` 保存明确选择的连线边，值为 `top/right/bottom/left`。省略 `target` 表示自动选择入边；旧数据没有该映射时继续按原有自动连线展示。
- `DETAIL`：`id`、`title`、`items: [{ id, text }]`，用于一份独立的详细步骤说明；可以携带 `imageUrl`、`videoUrl`。旧 `materials`、`safetyNotice` 数据兼容保留，但不再提供编辑、阅读区域，也不参与新正文的组合。

模块在数组中的顺序保留创建与兼容读取顺序，画布位置和箭头分别表达布局与先后关系；详细步骤的顺序由该类型条目在数组中的先后决定，`items` 顺序决定一份说明内清单的阅读顺序。所有清单内容均由用户手动编写，不生成每日任务或执行状态。模块和详细步骤分别最多 100 个，每份详细步骤包含 1–100 条非空清单条目。允许保存没有模块或详细步骤的空白模板。

编辑器和阅读页复用同一块自由画布，界面提供整体显示缩放。默认显示比例固定为 100%，不随 `.flow-board-viewport` 的可用宽高自动变化；用户可用减号、加号或右下角把手在 5%–200% 间缩放，不提供百分比输入。包含坐标轴、文字、方框、端口和箭头的整个 plane 通过 CSS transform 等比显示，stage 占据缩放后的范围，滚动限制在画板区域内。偏好按流程 ID 保存到本机 `workflow-os:board-zoom:<id>`，刷新恢复，各流程独立；旧 manual 比例继续使用，旧 fit 偏好回退到 100%。缩放不提交接口、不改修订号或工作内容。拖动预览可用 Esc 或触控取消恢复，键盘方向键也可调比例。

`autoLayout.ts` 在本机生成「整理位置」方案，沿用完整流程的依赖顺序作为摆放顺序，但不改变 steps 数组顺序或箭头。固定时间轴坐标，优先级轴仅在原档位内避让；没有坐标轴的方向按 24 像素间隔摆放，尺寸和画布范围保持不变。放不下的工作保留原位置，并作为障碍重新计算其他工作；最终检查不引入原本不存在的重叠。仅改动确实移动的模块 frame，原文、做法绑定、附加字段、尺寸和连线端口原样保留。`AutoLayoutControls` 用只读 SVG 比较原图和方案，取消或打开预览不写数据。明确应用前检查快照内容仍一致，然后走现有 expectedRevision 和 draftOnly 原子保存；新建流程只更新编辑器草稿。

「文字生成流程图」的当前版本完全在浏览器内运行。`localTextDiagram.ts` 提供纯函数 `parseLocalTextDiagram(text)`，输入最多 16000 字，输出 `{diagram,notices}`。规则识别流程标题、工作名称与冒号、多行说明、同层编号与子步骤、自然段、顺序词及箭头；引号、括号、URL、时刻与小数采用保护规则，工作名称按原文提取并消除重名，具体做法保存连续原文片段，不补写内容。超过 60 项工作或输入上限时明确报错，不截断。清晰顺序按阅读顺序连线；出现未引用的条件、并行或返工词时保留方框和原文，关闭推断连线并提示用户核对。混合格式仍须在预览中检查工作划分，统一「名称：做法」格式更可靠。生成过程不调用网络、模型或密钥。

`textDiagram.ts` 为生成结果创建全新的模块、具体做法和清单编号，使用本地固定 detailId 一一绑定，保持原文和原先后关系。图按强连通分量分层后从左到右摆放，分支分行、长图分带，所有工作在 320–2400 像素画布内且不重叠；循环、独立工作和对应端口保留。默认关闭坐标轴，不从未声明的内容推测时间或优先级。`TextDiagramControls` 只在点击「免费生成预览」时运行本机解析与排版；所有工作、原文做法和生成提示均可核对，修改输入后不允许保存旧预览。明确添加时通过现有 draftOnly 保存创建独立新流程，不修改当前流程。每份预览固定 createRequestId 和首次提交的名称；服务端在组织锁内将该编号作为新 SOP 编号，重试只返回同组织已创建的 SOP，不覆盖其后来修改的内容；跨组织冲突和更新/创建混用拒绝。不需要数据库迁移。

旧 `GET/POST /api/orgs/{org}/diagram-preview` 保留兼容，但 `workflow.diagram.enabled` 在配置和构造注入中均默认 false。读取到密钥也不会启用付费功能；GET 返回不可用，POST 在构造或发送外部请求之前拒绝。当前界面没有付费接口入口。原有服务的超时、权限和校验测试保留，免费关闭路径另有生产 Bean 和 MockMvc 覆盖。

「模版大小」对话框分别设置画布的逻辑宽、高，每项为 320–2400 像素的整数。应用时只改变空白范围，已有工作 `frame` 的逻辑位置和宽高保持不变；旧比例工作按修改前的画布尺寸转为固定 `frame`，`referenceCanvas` 保留原参考大小。新宽、高不得小于现有工作边界，不会通过挪动或缩小工作来适配。尺寸写入 `boardSettings.canvas`，并保留坐标轴、箭头和具体做法；已有流程自动保存，新建流程仍随明确点击「添加流程」一起创建。

原有 `boardSettings.canvas`、`referenceCanvas`、工作 `frame: {x, y, width, height}` 和旧比例 `position` / `size` 数据继续读取，不因显示缩放改写。新工作默认宽高各为参考画布的 20%，工作本身仍能独立移动和调整大小。屏幕指针位移除以当前 scale 后换算为逻辑坐标；SVG 端点通过同一 transform 对齐。开始移动（包括键盘 Space 尚未位移）、调整工作大小或画箭头时锁定显示缩放，取消后解锁，避免交互期间使用旧比例快照。DnD Kit 提供指针、触摸与键盘移动，不吸附网格或交换数组顺序；移动把手与做法名称链接保持独立。

工作之间可从方框四边任一圆点拖线，移动时显示箭头预览并高亮目标，放下后建立连接。拖到目标方框自动选择入边，拖到目标圆点则固定目标边；点击或键盘选择圆点同样可用。同一来源换圆点会改变待连接的起点，重复点同一圆点、点空白处、Esc 或触控取消则清除选择且不保存。重复连接同一对工作仍拒绝，换边时先删原箭头再连接；删除箭头同时清除其端口映射。移动工作或改变矩形模板尺寸时保留选边，路径避让来源和目标方框。顶部不再提供画箭头开关；移动手柄与做法名称链接继续独立工作。

调整工作大小与移动、画箭头分别使用自己的把手；调整方框大小时固定其左上角位置，实时更新连接箭头的端点。交互限制最小可操作尺寸及画布边界；拖动过程中按 Esc 或触控取消会恢复原尺寸且不保存。尺寸数据使用同一流程保存接口，后端校验逻辑像素 frame 的有限数值、至少 32 像素的宽高及画布边界；旧比例数据继续兼容。

流程可选的时间线与优先级保存在流程字段 `boardSettings` 中，以 JSON 字符串表示，不放进 `steps` 或独立工作记录：`{version: 1, timeline: {enabled, startMinute, endMinute, axis?, focus?, segments?}, priority: {enabled, axis?}, canvas?: {width, height}}`。轴设置与模板尺寸互相保留。方向为 `x`（从左到右）或 `y`（从上到下）；旧设置缺少两个方向时默认时间横向、优先级纵向，仅缺一个时推断为另一个的相反方向。两项同时启用时不能使用同一轴，对话框中更改任一方向会自动互换另一项；单独启用一项也可选择方向。旧流程没有设置时，两条轴均关闭。时间范围使用 0–1439 的整数分钟，起止不能相同；结束早于开始表示跨午夜到次日。两条轴分别开启或关闭，在「时间和优先级」对话框中应用；取消、Esc 或无效范围不提交。

`timeline.segments` 为可选的 `null | Array<{startOffset, endOffset, scale}>`，最多 96 段。offset 是相对开始时间的累计整数分钟，满足 `0 <= startOffset < endOffset <= duration`，须按起点升序且互不重叠，可相接或留空隙；`scale` 是 `1e-6–10000` 的有限权重，空隙按 1 计算。正向映射按各段分钟数乘权重累计并归一，反向映射使用同一分段表。轴刻度使用正向映射，工作时间使用反向映射；优先级继续线性计算。旧 `timeline.focus` 的 1–10 倍单段格式继续支持；只有 segments 缺省才回退到 focus，显式 null 或 [] 表示均匀间距，防止旧 focus 重新生效。非法可选分段读取时只丢弃分段字段，写入时则拒绝整笔请求。

时间刻度合并所有绝对整点、首尾、已存 focus/segments 边界，不再使用 maxTicks 抽稀；原有非整点断点保留，避免旧映射转换时改变时段内斜率。长度列表按正向映射差乘画板时间轴边长显示逻辑像素，与本机缩放比例无关。输入单段长度时以各段 `length / duration` 重建完整 segments，其他段长度保留，时间轴方向的 canvas 边长按总长取整；每次重建的总长舍入误差小于 1 像素。拖动内部刻度只向相邻两段借长，总长保持；拖末端刻度只改变最后一段和总边长。被编辑的段最少 24 像素，总边长沿用 320–2400 限制；旧过短段先保留读取，无法借长时提示先输入足够长度。

前后时间线均开启、方向和整体起止时间不变时，改变分段或旧 focus 会在同一次保存中转换受影响的工作原点：先从旧可移动行程反算未取整的时间，再按新映射换算位置，保留固定尺寸、另一轴坐标、编号、箭头和具体做法。长度调整与 canvas 同时变化时先重新定位，再检查新边界能否容纳方框；单纯修改画板宽高仍保留位置和大小，并使用原有占用范围校验。旧比例坐标会转换为固定 frame，原始大小参考 referenceCanvas 保留。分钟显示先稳定到 1e-9 分钟再取整，避免半分钟因反算误差发生一分钟跳动。

`TimelineAxis` 用指针捕获处理鼠标和触摸，屏幕位移除以开始时的实际缩放比例再计算逻辑像素；拖动中只生成本地 settings/frames 预览，松开后一次原子保存，取消、失焦、丢失捕获或 Esc 不写远端。方向键在按下到松开期间预览，松开保存，默认 8 像素，Shift 为 1 像素。调整期间禁用其他画板操作，保存使用已有 expectedRevision 冲突保护；已有流程编辑沿用自动保存，新建流程仍须明确创建。

界面改变整体起止时间会显式清除 focus 和 segments；同时改变方向或时间范围时采用新坐标含义，不执行保时重排。旧客户端未提交已存 segments/focus 且时间范围和实际方向未变时，后端保留对应字段；改变范围或方向则清为 null。缺省从未存在 segments 的旧配置不会被凭空添加 segments:null，从而保留旧 focus 客户端的语义。合并后重新校验，非法配置与对应工作更新整笔回滚，不需要数据库迁移。

时间沿所选轴由早到晚，优先级沿所选轴依次为「优先做」「正常安排」「可以稍后」。轴在实际画布外布局，不改变模块的比例坐标；时间和优先级都按方框可移动范围计算进度：横向为 `x / (1 - width)`，纵向为 `y / (1 - height)`。贴到起始边为 0，贴到结束边为 1，时间线两端和优先级首末档均可到达，三档优先级按可移动范围等分。方框占满该轴、没有可移动距离时进度为 0；拖动及调整大小均使用预览位置与尺寸重新计算。配置通过同一带修订号的流程保存接口持久化，已有阅读页直接保存，已有编辑器防抖自动保存，新建编辑器随明确创建一起提交；配置修改不改变工作标识、箭头或具体做法，方向字段复用原存储而无需数据库迁移。

新建编辑器 `/workflows/new` 只在点击「添加流程」后提交一次创建请求。已有流程编辑器 `/workflows/:id/edit` 在最后一次修改后等待 700 毫秒，再提交有效内容；保存请求串行执行，同一时刻只有一个请求，后续修改等前一响应返回后再用最新修订号保存。名称、分类、具体做法、媒体和画布操作使用同一原子保存接口，携带 `expectedRevision` 并更新查询缓存，位置或连接修改保留详细步骤、媒体和旧版附加内容。点击「返回流程」会先提交尚未保存的有效修改，再返回阅读页。

已有流程编辑器直接展示表单，自动保存状态位于「返回流程」旁，通过 `role="status"` 显示「已自动保存」「正在保存…」「输入停下后自动保存」或「草稿已保留，补全后自动保存」；新建页保留「添加流程」标题。暂时不符合校验的内容不会提交；本地草稿按用户、组织和流程隔离，进一步以 `:tab:<UUID>` 分开每次编辑会话；保留兼容旧单键草稿，读取时排除 `:recovery:` 归档。写入后用 sessionStorage 的 `:active` 指针优先恢复本标签页的草稿，不可用时读取最新有效草稿。每个页面只清理自己写入或明确消费且原始字符串仍完全相同的快照，不清理其他页面的新修改。新建内容也备份到独立 new 草稿，仍仅在明确点击创建时发请求；创建成功先确认内容再清理快照，避免卸载时重新生成已创建稿。补全后已有流程继续自动保存。保存冲突（HTTP 409）会明确提示并保留本地输入，不用新修订号重试覆盖远端内容。已保存流程图的直接操作也调用同一原子保存接口；保存失败时明确提示。

流程卡片使用独立的容器包裹打开模板的链接和删除按钮，删除按钮不是链接的子元素。OWNER / MANAGER 可通过小垃圾桶删除模板，并在确认对话框中取消或提交；EMPLOYEE 不显示编辑删除按钮。流程图的工作按钮使用常显垃圾桶；已有流程编辑器删除工作后自动保存，新建流程中的删除随首次创建一起提交。工作清单行的删除按钮同样先打开确认对话框，确认后按模块标识从所属流程移除该模块及所有相连箭头，使用修订号提交原子保存，详细步骤和其他模块内容保持原样。

点击工作名称后，已有做法的阅读页仅展示命中的一份文档，不显示「其他工作」导航。可编辑角色打开尚无内容的工作时直接进入实际来源流程的 `/edit?detail=<规范名称>&from=<原流程>`，不经过加号或「写具体做法」引导；只读角色仅见空内容状态，不创建文档。外部别名沿用真实做法标题和来源，返回原流程。

已有流程的单项编辑通过 `detailId` 稳定选定文档，只渲染该份原序号的字段，隐藏流程信息、其他标签和添加文档入口；保存仍提交完整 draft，保留其他做法、模块与媒体。只打开的空白做法作为待填写项，不进入自动保存或本机备份；实际输入后再合并。切换同一流程的目标名称、改名或刷新时同步名称与 ID，避免串入旧内容或增加空白文档。新建流程内点工作同样进入单项编辑，保留流程名称、分类与创建按钮，可用「返回安排工作」回到当前草稿，仍只在明确点击「添加流程」时创建。

模块有 `detailId` 时按固定来源和文档编号查找，缺失时不回退同名文档；没有固定编号的旧模块继续按名称及可选来源匹配。首次创建/显式选择成功后固定编号，做法实际编辑时先固定旧对应再改名。名称执行 `trim()` 与 Unicode NFC 规范化后精确比较；大小写、标点或文字不同均不匹配，不进行模糊回退。同一类型内规范化后重名的内容不能保存，模块与其同名详细步骤可以并存。

未指定来源的模块优先匹配本流程唯一同名 `DETAIL`，没有本流程匹配时才查找当前手册其他流程的唯一同名 `DETAIL`。存在多份候选时不自行选中。用户在加号对话框切到「从工作清单选择」并选择某行后，模块保留该行来源的 `detailWorkflowId` 和 `detailId`（当前流程也固定来源）；没有编号的旧数据才按可选 `detailName` 或模块名匹配。来源或固定编号失效时明确提示，不新建替代文档。所有来源均来自当前手册的流程查询，组织成员及租户检查仍由后端执行。

工作方框的小铅笔打开「工作改名」对话框。名称规范化后相同则关闭而不保存，空白和重名会提示；取消及 Esc 不提交。本地配对的唯一 `DETAIL` 同步标题、保留正文和媒体；外部共享做法保留来源的 `detailWorkflowId` 与旧标题 `detailName`，不修改源流程。改名保留模块 ID、frame 与连接端口，已有阅读页直接保存，已有编辑器自动保存，新建内容仍等明确创建；工作清单沿用原记录并同步名称。

成功匹配的模块链接使用 `/workflows/:id/steps?name=...&detailId=...`；跨流程跳转附加 `from`，以保留返回原流程图的入口。尚未找到做法的模块链接附加 `module` 标识，保留明确选择的来源；从详情目录打开的普通链接优先读取该流程自己的说明，不受同名模块的其他来源影响。刷新或直接打开带编号的地址仍读取同一文档，编号已不存在时不会按同名替换；编辑页同样拒绝失效编号。做法页面通过「修改具体做法」进入编辑；未找到时显示缺少同名详细步骤和「写具体做法」入口。选择了已有来源但尚无清单时，补写入口进入原来源流程，其他引用该工作的模板会随之对应。详情可以先独立保存，模块也可以先保存后补写同名详情。

旧流程的每个事项兼容转换为同名模块与详细步骤，原说明成为手工清单内容，物料、注意事项、图片和视频继续保留。旧版本快照不改写。

当前前端使用原子保存接口：

```http
POST /api/orgs/{org}/sops/save
```

请求包含 `title`、`category`、`steps`，编辑时另外提交现有 `id` 与 `expectedRevision`；响应为保存后的 SOP。自动保存、已有画板编辑和工作清单移除工作使用 `draftOnly:true`，允许稳定唯一编号的 DETAIL 暂未命名、0–100 条步骤以及空字符串步骤，原样保留未完成内容；流程和 MODULE 名称、非空 DETAIL 名称唯一性、结构、媒体、布局、权限、组织和版本校验继续生效。草稿保存同步工作记录并递增修订，不创建历史版本，也不改变已有发布版本或发布状态。默认/false 的创建与正式发布继续严格要求完整做法。修订号用于识别基于旧内容提交的编辑，避免覆盖其他人的后续保存。接口失败不能留下部分结果。

模板删除使用 `DELETE /api/orgs/{org}/sops/{id}`，请求体提交当前 `expectedRevision`。保存和删除统一先取得组织锁，再取得流程锁，避免新建共享引用与删除竞态。删除先按与前端一致的旧名称/固定编号规则解析同组织来源；存在其他流程使用时返回 409 并列出流程及工作，不删除来源正文或历史。直接移除被引用 DETAIL 同样拒绝；提交后已经移除对应模块与做法、没有其他使用者时允许删除。新增或改变的显式绑定必须指向当前组织存在的来源和文档，原本就失效的旧绑定可以原样保留编辑。源做法改名时，在同一事务中为旧的唯一匹配引用补充固定来源与文档编号，不改正文、位置和发布历史；其他流程的修订号随正常持久化递增，过期编辑会收到冲突。原有旧任务/模板引用、角色、组织和修订检查继续生效。

原有创建、编辑、发布、版本读取和归档接口保留用于兼容。旧任务仍引用生成时的 SOP 版本；本次流程编辑不改写它们的历史快照。旧状态字段不再用于表达当前界面的待办或完成状态。

## 连续的完整操作流程

保存的框架页通过「生成完整流程」进入 `/workflows/:id/complete`。该页复用组织内已有流程查询，实时汇总被框架引用的工作与具体做法；查看、复制、打印与调序不触发保存、修订号、历史或工作清单变化。共有文档沿用 `resolveModuleLink` 的本地、同名、alias 与显式 pin 规则；同一文档用于多项工作时保留每次出现，不任选歧义来源。

可编辑角色也读取当前 user/org/workflow 隔离的本机编辑草稿，`completeWorkflowSources.ts` 只把本机做法合入汇总，不使用旧草稿的框架、位置、时间、标题或画板配置，保留服务端后来添加的做法。员工不读取这些草稿。若本机与服务端已有相同编号但内容不同、不同编号同名，或补存会改变已有模块对应的来源，默认整份来源使用服务器原记录，不提供自动补存按钮；正文外明确显示当前来源，只有用户点「查看本机草稿」才预览冲突本机内容，可随时切回。提示和选择控件不进入正文、复制或打印。安全补存由正文外的「保存本机做法」明确触发：重新读取最新服务端数据，先把原本机完整草稿存入同一隔离键的 `:recovery:<UUID>` 副本，再仅合入做法并带最新 expectedRevision 以 draftOnly 保存；确认成功且所选快照原文未变后才清理该快照键，保留其他标签页及旧归档。版本冲突、校验或网络失败均保留原稿。

`generatedWorkflow.ts` 计算匹配及顺序。有效箭头优先，通过强连通分量保留回路，再从当前可用的分量中逐次选择时间最早的一项，立即释放后继；不再整批输出所有零入度节点，以免晚间独立工作插入早间链条。无箭头时沿实际时间轴、尺寸与可移动行程反算分钟，兼容非线性间距、换轴、跨午夜及半分钟取整；无时间时使用框架原列表顺序。内部保留分支、汇合、无效连线和缺失状态，但不将这些系统信息写入正文。

`connectedProcedure.ts` 保留原清单顺序和工作的依赖模型。「调整衔接顺序」只允许同一分钟内换序，已有箭头须保留回路分量之外的全部依赖，未设置时间或箭头时可自由换序。选择按 user/org/workflow 隔离保存在本机，签名包含模块顺序、时间分组和连线；框架变化或无效旧选择回退到当前模版顺序；仅分组算法变化但模块/时刻/连线完全相同，且旧顺序仍合法时保留选择。调序只修改本机预览。

`completeWorkflowText.ts` 的 `completeWorkflowParagraphs` 以同一份 `entryOrder` 组织正文：使用生成器根据模板时间轴计算的 `entry.time` 放在工作名前，沿用精确分钟与「次日」格式，未设置时间时不补写时刻或时长；工作名后接非重复说明和原步骤，不带入旧的 `materials`、`safetyNotice` 字段，只整理标点，不增加连接词、条件、动作或重复次数。保留用户在步骤中填写的完整句子、数量、时间、否定和条件，包括准备或注意相关的实际步骤；共享做法按每次工作出现保留。无可用做法时保留已安排的时刻与工作名，不填占位说明。相邻工作合为连续段落，长正文只在工作边界分段。正文不生成全局编号、优先级标签、系统提醒、来源标签、步骤跳转、图片或媒体链接；用户实际在文字中填写的链接仍作为原文保留。

`WorkflowProse` 只用 React 文本节点渲染同一组段落，不解释 HTML。纸页仅含用户流程名和正文，调序、复制、打印与安全补存控件位于正文之外。剪贴板和不可用时的只读文本框都使用 `paragraphs.join("\n\n")`；打印保留同一纸页并隐藏操作控件。此功能无需后端、模型服务或数据库迁移。

## 独立工作记录

`work_items` 为每个模块保存一条独立记录，使用 `(workflow_id, module_id)` 唯一约束。记录包含自己的 `id`、组织、模板、模块标识、名称、创建与更新时间以及修订号；数据库中的旧 `notes` 字段继续保留。工作清单读取该表，不依赖临时展开模块来产生列表。模块名称同步到记录，界面显示工作名称、编号、所属流程、具体做法和操作五列。「在流程里查看」放在所属记录行内，不存在行选择状态或独立详情框，不提供备注列、编辑器或保存操作；可按工作名称、记录编号、模板标题和分类搜索，再按所属模板筛选；搜索去掉首尾空白、执行 Unicode NFC 规范化并忽略大小写，「显示全部工作」同时清空搜索与流程选择。

保存流程时，在同一事务中同步记录：新增模块插入一条记录；同一模块标识的移动、缩放、连接或改名保留记录 `id` 及已有数据；删除模块移除对应记录。读取旧手册时，在流程锁内为尚未登记的模块补建记录；旧格式标识与前端兼容读取保持一致，不改写旧正文和媒体。

`GET /api/orgs/{org}/work-items` 返回当前手册未归档流程的持久化记录。读取要求组织成员权限，资源查询同时限定组织与记录归属。旧 `PUT /api/orgs/{org}/work-items/{id}` 备注接口和字段保留用于兼容既有数据及客户端，仍要求 OWNER / MANAGER；当前前端不调用该写接口。位置与箭头保存仍走流程原子接口，后端验证尺寸与坐标边界、模块标识唯一性和箭头终点属于同一模板，禁止重复和自连接。

## 文字和原图互相还原

`workflowTransfer.ts` 提供版本化可还原文字：可读正文后附 BEGIN/END 标记和 JSON 快照。序列化保存 raw steps、原始 boardSettings 字符串、标题和分类、正文、完整流程顺序及已确定对应的做法副本。普通文字解析返回 null；损坏标记不会进入普通文字拆分。校验名称、编号、布局、端口、来源一致性、100 工作与 100 做法上限、2 MB 长度和 JSON 深度。还原保持工作编号及几何布局，原流程自身引用转为本地引用，跨流程做法按快照复制；同一来源复用副本，副本编号或名称碰撞时区分，模块名称和位置不变。明确引用缺失副本时拒绝，不以同名内容替代。媒体只保留链接，不打包文件。

完整流程页只保留「复制全文」入口，直接复制可读正文和完整 transfer 快照，跨浏览器或跨设备粘贴也能还原原图。原来的「复制还原文字」不再单独显示。异步剪贴板不可用时，备用框提供与按钮相同的完整传输文字。页面正文、打印和手动选中正文复制仍保持纯正文，附带数据和备用框位于正文、打印区之外。

明确点击「复制全文」并复制成功、手动复制正文的 onCopy 仍会调用 `workflowCopySnapshots.ts`，把纯正文与当时完整 transfer 快照关联，按 user/org 隔离保存在本机，兼容后续只粘贴正文的用法；打开页面或渲染不记录副本。完整备用文字自带图形数据，不依赖额外本机记录。记录在异步剪贴板调用前捕获，复制成功后才提交关联，失败不会替换此前成功复制的原图；原图后来改动不会改变已经复制的布局。单次在途锁和来源签名继续防止重复调用及过期成功提示。副本按来源编号与全文去重，保留最近 20 份并受总大小限制；本机存储不可用时保留有界内存副本。

`TextDiagramControls` 导入依次识别标记格式、本机最近明确复制的匹配副本、当前流程库完全匹配的正文，最后才对新文字运行普通拆分和排版。`plainTextWorkflowRestore.ts` 以原正文、合法手动顺序及其具体做法生成验证过的快照；兼容 CRLF 和首尾空白，也允许手动复制时带上原流程标题，不忽略内部文字、标点或空白差异。当前流程页明确的来源可用于选定原图；没有明确来源且多张图具有相同正文时，展示名称和工作数供选择，不默选较小图。复制副本优先还原当时图形，旧文字未记录副本时才对比当前库；流程库未读完或已匹配原图却无法完整还原时明确报错，避免悄悄把 33 项工作按三段正文拆为 3 项。

匹配到原图后直接复用完整 transfer 导入，不重新排版。依赖当前库的预览通过规范化快照签名判断来源是否变化，后台刷新期间不采用旧缓存，首次保存前重新读取并核对；复制副本与标记格式则保留自身记录的图形，不依赖当前库。仅未匹配的新文字适用普通 16000 字、60 项工作上限，还原格式仍最多 2 MB、100 项工作，输入框不截断。保存沿用 draftOnly 和 createRequestId，结果不明时沿用原请求重试，新流程不修改原数据。上述识别、快照和预览都在浏览器本机运行，不调用外部模型或付费接口。

`workflowTextOrigin.ts` 在首个步骤的保留字段 `workflowOSOriginalText` 中保存输入原文、合法顺序及全图和已解析做法的规范化签名。签名排除该字段，避免重复还原时嵌套增长。完整流程优先使用仍匹配的原文和顺序，保持空格、换行及标点，正文继续 React 转义并使用 pre-wrap。移除准备和注意事项的专用界面不改写明确输入的原文，也不迁移旧数据或传输快照。图、做法、时间设置或显示顺序变化后，不再使用旧原文；仅 JSON 属性顺序或设置格式化变化不会使签名失效。无需修改后端或数据库。

## 图片与视频

图片可通过受保护的组织文件接口上传，支持 PNG / JPEG，最大 5 MB，限制解码后的像素总量。上传后返回组织内 `/api/orgs/{org}/files/{id}` 地址。读取文件再次校验成员权限，不暴露公共文件目录。

步骤媒体链接允许 HTTPS 或当前组织的受保护文件地址。视频采用链接形式，当前没有视频上传或托管服务。数据库中的媒体记录与磁盘文件需要一起备份，当前没有孤立图片清理作业。

## 存储与运行

Flyway 管理数据库 schema；JPA 仅 validate，不自动修改结构。开发环境使用 H2 文件库，部署方案使用 PostgreSQL；流程继续复用现有表结构。个人模式 V3 迁移新增 `personal_installation`，V4 新增独立的 `work_items` 表，读取旧手册时补建一对一记录，不删除此前的地点、计划、任务、规则或交接数据。

实体时间使用 Instant，并以 UTC 持久化。地点时区、业务日期和重复规则仍供旧接口使用，当前流程库不需要用户选择日期、时区或地点。

Compose 使用 PostgreSQL 16、Java 21 后端和 Nginx 前端，前后端同源以使用 Cookie。HTTPS 部署时须设 COOKIE_SECURE=true。当前没有持久化分布式 Session，多副本部署需补充会话共享方案。实际 PostgreSQL、Compose、HTTPS 和恢复流程的验证状态见 `testing.md`。
